# Bloom · Match-3

Самостоятельная браузерная игра на JavaScript, HTML и CSS. 10 уровней, карта путешествия, четыре бустера и все 10 парных комбинаций, вложенные ящики, цели, ограничения ходов и визуальные читы. Интерфейс на русском; мышь, сенсорное управление и клавиатура. Иллюстрации — собственные SVG в `src/textures/`. Серверная часть и установка пакетов не нужны.

## Краткое описание кода

Проект разделён на независимый игровой движок и браузерный интерфейс. `src/main.js` создаёт UI-контроллер и запускает приложение, а `src/engine.js` служит публичной точкой входа в игровую логику.

- `src/core/` — поле, поиск совпадений и доступных ходов, обмен фишек, каскады и гравитация.
- `src/boosters/` — эффекты четырёх бустеров и правила их парных комбинаций.
- `src/entities/` — модели фишек, бустеров и ящиков, включая правила получения урона.
- `src/goals/` — учёт прогресса и проверка выполнения целей уровня.
- `src/levels/` — декларативные конфигурации и загрузка десяти уровней.
- `src/ui/` — отображение поля и HUD, ввод, диалоги, звук и анимации.
- `src/styles/` и `src/textures/` — оформление интерфейса и SVG-текстуры.
- `tests/` — автоматические и ручные проверки механики, архитектуры и отображения.

Основной сценарий хода выглядит так: контроллер передаёт действие игрока в `Game`, движок проверяет обмен, находит совпадения, применяет эффекты и гравитацию, обновляет цели и отправляет UI асинхронные события для анимации. Движок не зависит от DOM, поэтому его правила можно детерминированно тестировать отдельно от интерфейса.

## Запуск

С Node.js 20+:

```sh
npm run dev
```

Откройте http://localhost:4173. Другой порт: `PORT=8080 npm run dev`.

Без Node.js можно использовать `python3 -m http.server 4173` из корня проекта. Открывать index.html через file:// нельзя: используются ES-модули.

```sh
npm test
npm run build
npm run format:check
```

Сборка копирует готовое приложение в `dist/`; эту папку можно разместить на любом статическом HTTP-сервере. Рабочих npm-зависимостей нет. Google Fonts необязательны: при отсутствии сети используются системные шрифты.

## Управление

- Перетащите фишку на соседнюю или нажмите последовательно на две соседние фишки.
- Повторное нажатие на выбранный бустер активирует его. Обмен с обычной фишкой тоже активирует бустер, обмен двух бустеров запускает комбинацию.
- Радужный шар при обмене собирает цвет соседней фишки; при самостоятельной или цепной активации выбирает цвет незавершённой цели, иначе самый многочисленный цвет.
- Стрелки перемещают фокус по полю, Enter выбирает фишку. Подсказка показывает допустимый обмен.
- После победы следующий уровень открывается автоматически через 2,2 секунды; после поражения текущий уровень перезапускается. Кнопка результата позволяет продолжить сразу. После десятого уровня начинается новый круг.
- Панель «Режим тестирования»: выбор любого уровня, победа и поражение. Все уровни также доступны с карты для удобного просмотра.
- Прогресс карты и последний открытый уровень сохраняются в localStorage. Незавершённое поле не сохраняется.

## Механика

Стартовые случайные клетки подбираются без горизонтальных/вертикальных матчей и квадратов 2×2. Заданные клетки сохраняются, включая цвет с индексом 0. Невозможная карта с принудительным стартовым матчем явно отклоняется.

Ход: обмен → проверка → эффект удаления → изменение поля → падение → повторные матчи → смена цвета ящиков → проверка целей/ходов. На время цепочки ввод заблокирован. Невалидный обмен возвращает фишки и не расходует ход. При отсутствии ходов поле перемешивается без стартовых матчей. Победа на последнем ходу имеет приоритет над поражением.

Бустеры создаются на месте участвовавшей в матче переставленной фишки. При каскаде — в одной из клеток группы. Приоритет пересекающихся фигур: 5 в ряд → Т/угол → 4 в ряд → квадрат. Сбор фишек засчитывается и при создании бустера. Цель сбора бустера означает его **активацию**, включая цепи и комбинации.

### Бустеры

- **Линия:** 4 в ряд, очищает ряд или столбец согласно направлению исходного матча.
- **Бомба:** Т/угол из двух пересекающихся троек, квадрат 5×5.
- **Радужный шар:** 5 и более в ряд, фишки выбранного цвета.
- **Самолётик:** квадрат 2×2, соседние клетки и выбранная удалённая цель. Сначала выбирает элементы незавершённых целей, затем разрушаемые ящики/бустеры; камни исключены.

### Все комбинации

1. Линия + линия: ряд и столбец.
2. Линия + бомба: три ряда и три столбца.
3. Бомба + бомба: квадрат 9×9.
4. Самолётик + линия: доставка линии к приоритетной цели.
5. Самолётик + бомба: доставка бомбы к приоритетной цели.
6. Самолётик + самолётик: три разные приоритетные цели.
7. Радужный шар + линия: фишки выбранного цвета превращаются в линии и активируются.
8. Радужный шар + бомба: фишки выбранного цвета превращаются в бомбы и активируются.
9. Радужный шар + самолётик: фишки выбранного цвета превращаются в самолёты и активируются.
10. Радужный шар + радужный шар: все фишки и бустеры; урон ящикам подчиняется правилам их типа.

Радужный шар в комбинации с линией, бомбой или самолётиком засчитывает каждую преобразованную фишку в её цветовую цель ровно один раз и начисляет 50 очков после анимации удаления. Каждый созданный бустер отдельно засчитывается при активации.

Попадание активирует другие бустеры через очередь; каждый бустер срабатывает не более одного раза за волну. Ящик теряет максимум одну жизнь за одну волну, даже если попал под несколько одновременных взрывов.

### Ящики

Обычный ящик получает урон от матча в ортогонально соседней клетке. Цветной — только от матча своего цвета. Меняющийся — то же правило, цвет переключается один раз после завершения каждого принятого хода. Прямое попадание любого бустера повреждает только обычный деревянный ящик; цветной и меняющий цвет ящики без соседнего матча нужного цвета не повреждаются. Это относится и к комбинациям, включая двойной радужный шар. Камень не получает урон, даже от двойного радужного шара.

Все ящики неподвижны, имеют `hp` и необязательное `contains`. После разрушения содержимое появляется в клетке; вложенный ящик сохраняет цвет, тип, жизни и своё содержимое. Содержимое не получает повторный урон той же волны. Фишка/бустер затем падает, вложенный ящик остаётся неподвижным. Содержимое неразрушимого блокера хранится, но естественно не освобождается. Ящики делят каждый столбец на независимые области падения; новые фишки верхней секции поступают из-за края поля, а нижних — из-за верхней границы своей секции. Изображение обрезается по этой границе: над свободной частью секции фишка невидима и не рисуется поверх ящика. Сначала завершается падение существующих фишек, затем начинается отдельная фаза появления новых.

## Конфигурация уровней

`src/levels/levels.js` содержит декларативные шаблоны `levelConfigs` с `placements`. `src/levels/LevelLoader.js` разворачивает их в карты; `src/levels.js` сохраняет совместимый экспорт `levels`. Каждый уровень:

```js
{
  id: 1,
  name: 'Первый росток',
  subtitle: 'Описание',
  rows: 7,
  cols: 7,
  colors: 4, // 3–6; палитра задана в entities/Piece.js
  moves: 24,
  goals: [{key: 'color:0', count: 18}, {key: 'box', count: 4}],
  map: [ /* rows * cols клеток, построчно */ ]
}
```

Клетка карты: `'?'` — случайный цвет; число `0..colors-1` — фиксированный цвет; `booster('line', 'v')` — бустер; `box('colored', 2, 0, box('wood'))` — цветной двухслойный ящик с вложенным обычным. Фабрики экспортируются из `src/engine.js`.

Ключи целей: `color:0`…`color:5`, `booster`, `booster:line|bomb|rainbow|plane`, `box`, `box:wood|colored|cycling|blocker`. Цели блокеров и их недоступного содержимого заведомо невыполнимы — не включайте их в обычные уровни.

## Расширение

`src/engine.js` — независимый от DOM движок. `Game` принимает генератор случайных чисел и асинхронный обработчик `animate(event, game)`, поэтому анимации можно заменить без изменения логики.

Новый тип ящика регистрируется через `registerElement(name, {canDamage, afterTurn})`:

```js
registerElement('armor', {
  canDamage: (item, hit) => hit.direct,
  afterTurn: (item, colorCount) => {
    /* дополнительное правило */
  },
});
```

`hit` содержит `direct` и множество цветов `colors`. Жизни, вложенность, подсчёт целей и неподвижность общие для всех типов. SVG нового типа добавляется в `src/textures/`, а его имя и выбор текстуры — в `src/ui/presentation.js`.

`src/main.js` запускает UI-контроллер, `src/app.js` сохраняет прежнюю точку входа; модули `src/ui/` отвечают за DOM, управление, SVG, диалоги и сохранение прогресса; `src/style.css` подключает отдельные файлы `src/styles/` с токенами, слоями доски, фишками, препятствиями, HUD, контролами, эффектами и адаптивностью. Режим reduced motion сокращает длительность анимаций.

## Проверки

`tests/engine.test.mjs`: распознавание всех фигур, начальные поля всех 10 уровней на 30 seed, допустимые/недопустимые обмены, цели, приоритет победы, последовательность анимаций, падение вокруг блокеров, все правила ящиков и вложенность, все 10 комбинаций и их области поражения, цепные реакции, расширение реестра. Дополнительно 500 ходов на 10 уровнях с проверкой целостности поля после каждого хода.

## Архитектура

- `core/Game.js` — совместимый API сессии и асинхронный канал событий. Старые импорты `engine.js` и `game/*` продолжают работать.
- `core/Board.js` — массив клеток, координаты и обмен элементов; `BoardInitializer.js` — генерация и перемешивание; `MoveFinder.js` — доступные обмены.
- `core/MoveResolver.js` — проверка обмена, расход хода, каскады и окончание хода.
- `core/MatchFinder.js` — поиск фигур; `boosters/MatchBooster.js` — приоритет создания бустеров.
- `core/Gravity.js` — расчёт нового поля и траекторий без изменения входного массива. Создание фишек передаётся функцией.
- `core/ResolutionWave.js` — накопление и применение урона, цепные активации. Удаление ожидает завершения анимации.
- `boosters/*Booster.js` — расчёт эффектов; `BoosterCombinationResolver.js` — комбинации; `TargetSelector.js` — приоритет мишеней.
- `entities/Piece.js` — фабрики и копирование; `entities/obstacles/rules.js` — расширяемые правила ящиков. Клетка — элемент либо `null`, отдельный класс без поведения не нужен.
- `goals/GoalManager.js` — счётчики и проверка целей; `types.js` — общий словарь JSDoc.

Зависимости направлены от UI к игровому API и доменным модулям. Движок не импортирует UI и не использует DOM. Читы вызывают `Game.forceOutcome`, а не самостоятельно изменяют игровые счётчики.

`tests/refactor.test.mjs` сравнивает 120 детерминированных ходов с SHA-256 снимками исправленного движка: начальные и итоговые поля, последовательность событий анимации, очки, цели, ходы и статус. Снимки исключают только глобальные числовые ID. Дополнительно проверяются неизменность входа расчёта падения и блокировка читов во время хода.

Оставшиеся ограничения: внешний API допускает изменение живого массива `game.board`; это сохранено ради совместимости. Отмена Web Animations при смене сессии обрабатывается без прерывания хода. Произвольная ошибка стороннего обработчика `animate` всё ещё может прервать ход без отката; отдельной задачей остаётся восстановление таких внешних обработчиков.

Имена внутренних операций уточнены: `initializeBoard`, `shuffleBoard`, `findLegalMoves`, `resolveMove`, `resolveBoard`, `activateBooster`. Координатные методы `Board` называются `coordinatesAt`, `indexAt`, `neighborsOf`, `squareAround`, `lineThrough`. Прежние имена методов `Game` сохранены как совместимый фасад. HUD вынесен из `GameView` в `ui/HudView.js`.

## Pseudo-3D оформление

Объёмная золотистая рамка, утопленная бирюзовая доска, обновлённые SVG со светом сверху слева, трещины ящиков и отметки вложенного содержимого. Цели показывают собранное/необходимое количество и шкалу прогресса. Читы сохранены в отдельной DEV-панели.

`ui/motion.js` централизует Web Animations и reduced motion. `ui/animations.js` ожидает эффекты цепочки, затем удаление, раскрытие вложений, падение существующих фишек и отдельное появление новых фишек у верхней границы каждой свободной секции. Движок получает завершение события только после всех его визуальных фаз. Порядок генерации новых фишек и конфигурация уровней сохранены. Изменение урона ящикам может менять дальнейшие каскады и расход случайных чисел.

`tests/presentation.test.mjs` проверяет очередность эффектов, ожидание удаления, раздельное падение и spawn, отмену анимации, reduced motion, transform-позиционирование и автоматические переходы без повторного запуска. Подробный отчёт о редизайне: [DESIGN-REPORT.md](DESIGN-REPORT.md).

### Регрессии правил и траекторий

Проверяются прямые удары всех бустеров по каждому типу ящика, отсутствие ложной анимации урона, один урон при пересечении матча и нескольких бустеров, раскрытие вложенного цветного ящика. Для трёх преобразующих комбинаций радужного шара проверяются точный сбор цвета, очки, общие и типовые активации, ожидание удаления и победа на последнем ходу.

Геометрия падения проверяется без препятствий, с одним и несколькими ящиками, включая соседние ящики и край поля. UI-тест проверяет обрезку изображения между ключевыми кадрами, отдельную фазу появления и одинаковые конечные координаты с reduced motion.

При обновлении снимков 120 ходов выполнено сравнение с исходным движком: на уровнях 1–8 изменились только данные траекторий; первые расхождения уровней 9–10 — отменённый прямой урон цветным ящикам в клетках 20 и 25 соответственно. Контрольный запуск исходного движка только с исправленными правилами ящиков совпал с новой версией по полям, счётчикам, очкам и числу вызовов генератора на всех 10 уровнях, за исключением новых данных траекторий.

Для воспроизводимой браузерной проверки запустите `npm run dev` и откройте [сценарии приёмки](http://localhost:4173/tests/manual.html). Кнопка запускает 15 фиксированных сценариев с настоящими `GameView` и `GameAnimations`; переключатель эмулирует reduced motion только на странице проверок. Оба прогона (15/15) проверены в браузере; также проверены комбинация радужного шара с линией на уровне 9, автоматический переход на уровень 10 после победы и его повтор после поражения. Страница проверок не включается в `dist/`.
